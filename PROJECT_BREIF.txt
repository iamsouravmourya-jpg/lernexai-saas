LERNEXAI PROJECT MASTER AUDIT
=============================
Updated: 27 July 2026

Purpose
-------
This document is a shareable deep audit of the current LernexAI codebase. It is intentionally more detailed than a normal brief so another AI can understand the product, architecture, feature coverage, technical debt, risks, and next priorities without needing extra context.

1. PRODUCT SUMMARY
------------------
LernexAI is a React + TypeScript SaaS learning platform built with Vite. It combines a marketing website with a protected learner app. The core product flow covers:
- account creation and login
- course browsing and enrollment
- lesson consumption inside a learning workspace
- AI tutor assistance
- module quizzes and final exam completion
- Pro upgrade via Razorpay
- certificate-related pages and purchase screens

The current flagship course focus is Microsoft Excel Essentials.

2. HIGH-LEVEL ARCHITECTURE
--------------------------
Frontend stack:
- React 19
- TypeScript
- Vite
- Tailwind CSS 4
- Wouter routing
- Framer Motion
- Radix UI
- Lucide icons
- TanStack React Query

Backend and data:
- Supabase Auth
- Supabase PostgreSQL
- Row Level Security
- Supabase Edge Functions

Payments:
- Razorpay Checkout
- server-side order creation and signature verification through Supabase Edge Functions

AI tutor:
- Groq-backed AI tutor
- lesson-aware context loading
- chat history persistence
- daily usage limits enforced through Supabase-backed logic

4. END-TO-END USER JOURNEY
--------------------------
1. User lands on the public marketing site.
2. User signs up or logs in through Supabase Auth.
3. User browses available courses.
4. User opens a course detail page and enrolls.
5. User enters the learning workspace.
6. User reads lessons, tracks progress, and can ask the AI tutor questions.
7. User attempts module quizzes and receives saved feedback.
8. User takes the final exam with timed, server-graded questions.
9. User reaches certificate and payment-related pages.
10. User can upgrade to Pro through Razorpay.

The strongest part of the flow is the learning and tutor experience. The weakest part is the certificate handoff, which is not yet fully end to end.

5. FEATURE INVENTORY BY AREA
----------------------------
5.1 Marketing and public site
- Landing page sections for hero, features, pricing, testimonials, FAQ, founder story, contact, privacy, and terms.
- Public pages are structured as a conversion-oriented front door.
- This side of the app is visually important because it is the first impression for new users.

5.2 Authentication
- Email/password sign-in and sign-up.
- Google OAuth support.
- Protected route handling with loading states and redirects.
- Auth state is managed in `src/context/AuthContext.tsx`.

5.3 Dashboard and learning entry
- Dashboard shows latest enrolled course, progress, and a continue-learning path.
- My Learning provides a broader list of enrolled courses.
- Continue-learning cards and progress bars are used to re-enter the course quickly.

5.4 Course browsing and detail
- Browse page shows the catalog.
- Course detail page shows course information and enrollment action.
- Course content is Supabase-driven rather than hardcoded UI only.

5.5 Learning workspace
- Three-panel learning layout with module sidebar, lesson content, and AI tutor panel.
- Previous / next lesson navigation.
- Lesson completion persistence and module progress tracking.
- This is the main product surface after enrollment.

5.6 Quizzes and exams
- Module quizzes exist with saved attempts and feedback states.
- Final exam has timed questions, scoring, and result review.
- The final exam flow is implemented, but the handoff beyond the exam still needs work.

5.7 AI tutor
- `src/components/AIChatPanel.tsx` is the active tutor UI.
- `src/lib/aiTutor.ts` is the client API wrapper.
- `supabase/functions/ai-tutor/index.ts` is the active server function.
- Tutor responses are lesson-aware and chat history can be restored.
- Usage limits are enforced for free vs Pro users.

5.8 Payments and upgrade flow
- Razorpay checkout is implemented for Pro upgrade.
- Order creation and payment verification are handled server-side through Edge Functions.
- Plan metadata is updated after successful payment.

5.9 Certificates
- Certificate pages and checkout pages exist.
- The certificate journey is not yet fully authoritative or fully complete end to end.
- Current client-side state handling is a major weakness here.

5.10 Database and backend
- Supabase SQL files define RLS, quizzes, final exam, and payment tables.
- Foreign key fixes were added for learning-related tables.
- AI tutor has supporting tables and RPCs for usage tracking and chat history.

6. DATA FLOW AND STATE MANAGEMENT
---------------------------------
Auth and session:
- Supabase Auth determines the signed-in user.
- Protected routes use auth state to guard app sections.

Course and progress data:
- Course, module, lesson, enrollment, and progress data are loaded from Supabase-backed helpers.
- `src/lib/course.ts` is the main data helper layer for the learning product.

Quiz and final exam data:
- Quiz attempts and final exam logic are split across dedicated helpers and SQL files.
- `src/lib/finalExam.ts` supports the final exam flow.

Payments:
- `src/lib/razorpay.ts` coordinates client-side payment initiation.
- Edge Functions handle order creation and verification.

AI tutor:
- `src/lib/aiTutor.ts` sends chat requests to the AI tutor Edge Function.
- The server function loads lesson, module, and course context, checks enrollment, stores chat history, and applies usage limits.

Certificate state:
- Some certificate purchase/completion state is still derived from `localStorage` on the client.
- This is the biggest trust-model problem in the app because it is not server-authoritative.

7. CONFIRMED ISSUES, BUGS, AND GLITCHES
---------------------------------------
Severity table:

| Severity | Area | Finding | Why it matters | Files |
| --- | --- | --- | --- | --- |
| High | Certificate trust model | Certificate purchase and completion state is stored in `localStorage` and then read back from the client | This is not server-authoritative, can desync across devices, and is easy to tamper with for UI state | `src/pages/CertificateCheckoutPage.tsx`, `src/pages/Certificates.tsx`, `src/pages/Dashboard.tsx` |
| High | Completion flow | The final-exam to certificate handoff is still incomplete | Learner flow stops short of a clean certificate issuance or download path | `src/pages/FinalExam.tsx`, `src/pages/Certificates.tsx`, `src/pages/CertificateCheckoutPage.tsx`, `src/pages/CertificatePage.tsx` |
| Medium | Bundle size | Production build warns that the minified JS chunk is above 500 kB | Larger initial payload can slow first load, especially on mobile | App route chunks |
| Medium | Build hygiene | Sourcemap warning is emitted for `src/components/ui/tooltip.tsx` | Build noise and possible cleanup needed | `src/components/ui/tooltip.tsx` |
| Medium | Legacy code | `src/pages/Player.tsx` is not routed | Dead code increases maintenance cost and can confuse future work | `src/pages/Player.tsx`, `src/App.tsx` |
| Medium | Legacy tutor component | `src/components/AITutor.tsx` exists but is not imported anywhere | Duplicate tutor UI path adds clutter and can drift from the real implementation | `src/components/AITutor.tsx` |
| Medium | SQL maintenance risk | Several SQL files cover quiz setup, attempts, and module quiz behavior with overlapping structure | Easy to let migrations drift or duplicate logic over time | `supabase/quiz_attempts.sql`, `supabase/module_quizzes.sql`, `supabase/module_quiz_setup.sql` |
| Medium | Production noise | The AI tutor edge function contains debug logging | Fine for debugging, but noisy logs are undesirable in production | `supabase/functions/ai-tutor/index.ts` |
| Low | Type safety | Some pages still use `catch (err: any)` patterns | Weakens compile-time safety and can hide useful error detail | `src/pages/Auth.tsx`, `src/pages/Upgrade.tsx` |
| Low | Scalability | Several flows still feel Excel-first rather than fully course-agnostic | More courses will require more abstraction work | `src/lib/course.ts`, `src/lib/finalExam.ts`, `supabase/final_exam.sql` |

Additional notes:
- The AI tutor flow itself is functional and lesson-aware.
- The main risk is not the tutor logic; it is the surrounding production polish and data integrity in the certificate and entitlement paths.

8. UI / UX AUDIT
----------------
8.1 Dashboard
- The dashboard is information-dense.
- Latest course, progress, CTAs, and extra status sections compete for attention.
- On smaller screens, the page likely feels busy and card-heavy.
- The main issue is hierarchy, not correctness.

Relevant files:
- `src/pages/Dashboard.tsx`
- `src/components/ContinueLearningCard.tsx`
- `src/components/CourseProgressBar.tsx`

8.2 Learning workspace
- This is the most complex screen in the app.
- The three-panel layout is strong on desktop but can become cramped on narrower viewports.
- Sidebar, lesson content, and AI tutor all demand space at the same time.
- This can create scroll fatigue and weak reading width.

Relevant files:
- `src/pages/Learning.tsx`
- `src/components/ModuleSidebar.tsx`
- `src/components/LessonContent.tsx`
- `src/components/AIChatPanel.tsx`

8.3 Certificate screens
- Certificate checkout, certificates overview, and certificate rendering are split across separate screens and state sources.
- The trust cue is weak because the client can make the UI think something is purchased even when the source of truth is not strong enough.
- These pages need a more confident hierarchy and clearer status messaging.

Relevant files:
- `src/pages/Certificates.tsx`
- `src/pages/CertificateCheckoutPage.tsx`
- `src/pages/CertificatePage.tsx`

8.4 Browse and course detail
- These pages are structurally fine but can feel card-heavy and repetitive.
- They would benefit from stronger typography, spacing discipline, and clearer CTA separation.

Relevant files:
- `src/pages/Browse.tsx`
- `src/pages/CourseDetail.tsx`

8.5 Landing pages
- The marketing site is polished, but it is section-heavy.
- The conversion path would be clearer if the hero, value proposition, and CTA stayed more dominant.
- Some sections could be tightened to reduce vertical drag.

Relevant files:
- `src/pages/Home.tsx`
- `src/components/landing/*`

8.6 Mobile polish
- Mobile-safe work already exists, but the densest screens still need another pass.
- Highest-risk areas are Dashboard, Learning, and Certificate screens.
- The best improvement likely comes from simplifying layout stacks rather than adding more UI.

9. TECHNICAL DEBT AND MAINTENANCE RISKS
---------------------------------------
- Client-side entitlement logic exists where server truth would be safer.
- Dead or legacy files are still present.
- Overlapping SQL scripts increase schema maintenance cost.
- Route-level code splitting is still needed to reduce the initial JS payload.
- Error handling is inconsistent across some pages.
- Debug logging remains in at least one edge function.
- The current product leans hard into Excel, so adding more courses will require more abstraction.

10. VALIDATION STATUS
---------------------
- TypeScript typecheck passes.
- Vite production build passes.
- Build warnings remain:
  - large JS chunk above 500 kB
  - sourcemap warning from `src/components/ui/tooltip.tsx`
- This report did not change runtime app logic.

11. RELEASE READINESS
---------------------
Currently strong:
- auth flow
- course browsing and enrollment
- learning workspace
- AI tutor
- module quizzes and final exam core logic
- Razorpay payment flow with server-side verification

Still not release-clean:
- certificate entitlement and completion trust model
- final exam to certificate handoff
- mobile polish on dense pages
- bundle size and split-chunk optimization
- test coverage and production hardening

12. PRIORITY FIX ORDER
----------------------
1. Move certificate and entitlement state to server-authoritative storage.
2. Complete the final exam to certificate and download handoff.
3. Remove dead code and consolidate the tutor path.
4. Reduce bundle size with route-level splitting and load optimization.
5. Rework Dashboard and Learning for clearer hierarchy on smaller screens.
6. Normalize error handling and reduce debug logging for production.
7. Consolidate overlapping SQL and migration logic.
8. Add more automated tests around auth, learning, quizzes, and payments.
